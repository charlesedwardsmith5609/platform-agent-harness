# Session permissions setup

This harness uses a reviewable **per-repo allowlist** instead of blanket Allow All. Repository
source declares routine capabilities; the human applies that source to machine-local settings,
then starts a new agent session.

## Files

- `setup/agent-permissions.json` — portable command policy. The location key is the placeholder
  `REPLACE_WITH_YOUR_REPO_GIT_ROOT`, never a machine-specific absolute path. Optional sibling
  `claude_permissions.ask` / `claude_permissions.deny` ship Claude Code defaults (aligned with
  agent-pairing-kit: ask `WebFetch`; deny environ/env/ssh/cloud-cred/metadata probes).
- `setup/apply_permissions.py` — substitutes the current Git root and writes gitignored local files,
  including Claude `allow` plus any `ask` / `deny` from the source. `--dry-run` prints the result
  and writes nothing.
- `.claude/settings.local.json` — Claude Code permissions (generated, not committed).
- `.claude/settings.json` — committed kit file, not generated by `apply_permissions.py`; see
  [Relation to `.claude/settings.json`](#relation-to-claudesettingsjson-kit).
- `.cursor/permissions.local.json` — resolved copy for Cursor-side review (generated, not committed).
  Cursor still relies on `CLAUDE.md` agreements for tool/network policy; deny/ask materialize for
  Claude Code.

## Matching granularity

Treat every identifier as an exact normalized prefix. A permission for a child command never grants
its parent or siblings.

- Prefer script-scoped Python approvals (`python setup/repo_issue.py:*`), never `python:*`.
- Prefer non-merge `gh pr` subcommands (`gh pr create:*`), never `gh pr:*` or `gh pr merge:*`.
- Do not auto-approve raw `gh issue:*`, `gh label:*`, `gh milestone:*`, or `gh project:*` —
  those run as children of the Python wrappers.
- Do not auto-approve `git push:*` (includes `--force`). Push remains a human-approved step;
  protect the default branch server-side against non-fast-forward pushes and branch deletion.
- Prefix rules cannot constrain arguments, so commands whose flags can write, spawn programs or
  reach out are not auto-approved by prefix: no `git remote:*`, `git pull:*`, `git stash:*`,
  `git worktree:*` or `git branch:*` (exact read-only forms `git remote -v`, `git branch --list`,
  `git branch --show-current` only), and `unittest` is limited to
  `python -m unittest discover -s tests`. `git diff|log|show` with `--output`, `git diff
  --no-index` and `git fetch --upload-pack|--exec` are in `claude_permissions.deny`.
- Git global options before the subcommand change the identifier. Do not run `git -c ...`.

Do not add `gh api` (including GraphQL) to the source. Issue hierarchy uses `gh issue edit`
`--add-sub-issue` / `--remove-parent` through `setup/repo_issue.py`.

`allowed_directories` must list only `REPLACE_WITH_YOUR_REPO_GIT_ROOT` so write access is scoped
to the repository checkout when permissions are applied.

The source excludes destructive git (`reset`, `clean`, `checkout`), account management, package
installers, blanket MCP access, inline `python -c`, and broad interpreter wildcards.

Fleet consumers that need `terraform` / `tflint` / `make` should add **narrow** prefixes in their
own fork of `setup/agent-permissions.json` after human review — they are intentionally absent
from the default harness policy. Do not auto-approve ambient cloud CLIs (`aws`, `az`, `gcloud`)
that inherit instance or user credentials.

**Threat model:** `deny` / `ask` reduce accidental exposure; they are a seatbelt, not a sandbox. Bash deny
patterns match literal strings and are trivially bypassed (variables, encoding, other tools). Bash
subprocesses can bypass `Read` denies unless matching Bash patterns are denied (the default
`claude_permissions.deny` list includes curl/wget metadata and cat/head credential-path
patterns for that reason).

Absolute paths in `Read` rules use the `//` prefix (`Read(//proc/**/environ)`); a single leading
`/` anchors at the settings source, not the filesystem root.

## Relation to `.claude/settings.json` (kit)

The agent-pairing-kit install added a committed `.claude/settings.json`. It is independent of this
workflow: `apply_permissions.py` neither reads nor writes it, and Claude Code loads it alongside
the generated `.claude/settings.local.json`.

- It sets `disableClaudeAiConnectors: true` and `enableArtifact: false`, asks before `WebFetch`
  (the same `ask` entry as `agent-permissions.json`), and has no `allow` list.
- Its `deny` list has 8 entries against 29 in the source's `claude_permissions.deny`. The `.env` /
  `.env.*` `Read` rules and the four `curl`/`wget` metadata rules are identical. It lacks the ssh, cloud-credential,
  `cat`/`head` and git-flag denies.
- Its two absolute-path `Read` rules (`Read(//proc/**/environ)`, `Read(//var/run/secrets/**)`) use
  the `//` form, matching `agent-permissions.json`. (An earlier kit version wrote them with a
  single `/`, which does not target the absolute paths; fixed in agent-pairing-kit `2ccbb85`.)
- The connector and artifact keys are not produced by `apply_permissions.py`; they exist only in
  the kit file. They were not exercised here, so their effect is unverified.
- `sync_harness_to_repo.py` does not copy `.claude/settings.json`, `scripts/` or `skills/`.

## Apply

1. Turn off Allow All.
2. From the repo root, preview:

   ```bash
   python setup/apply_permissions.py --dry-run
   ```

3. Apply (writes gitignored local files only):

   ```bash
   python setup/apply_permissions.py
   ```

4. Restart the agent session. Permission files load at session start.

Do not hand-edit generated local files to add absolute sibling or home paths. Change
`setup/agent-permissions.json` and re-apply instead.
